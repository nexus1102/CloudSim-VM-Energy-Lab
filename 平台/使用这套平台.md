# V1 使用与维护

项目现名 V1；历史算法修正版本仍标作 v10。本文所有命令在本文件所在的“平台”目录执行，不依赖项目的绝对位置或目录名。

## 环境

建议 JDK 8（当前随附 CloudSim 3.0.3、Commons Math 3.2），Python >=3.10；锁定依赖已在 Windows Python 3.12.7 验证。无需联网即可使用已满足依赖的本机环境。

runtime.ps1 集中选择环境。Java 顺序为 RESEARCH_JAVA_HOME、JAVA_HOME、PATH 中 javac 的同目录 java，最后为原工作站的 JDK 兼容路径。RESEARCH_JAVA_HOME/JAVA_HOME 必须是含 bin/java.exe 与 bin/javac.exe 的 JDK；显式路径错误直接报错。

Python 顺序为 RESEARCH_PYTHON、本地 .venv、PATH、旧 Codex 运行时，并检查 numpy、matplotlib、Pillow；RESEARCH_PYTHON 错误不会静默改用其他环境。Test 仅需 JDK。

需要隔离安装时：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
$env:RESEARCH_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
```

requirements.txt 锁定直接依赖，requirements-lock.txt 固定已验证环境的传递依赖。旧 PDF 提取/文档脚本另外依赖 PyMuPDF、reportlab，不在当前 Single/Matrix/图报告运行链内。

## 运行、核验与规模实验

```powershell
powershell -ExecutionPolicy Bypass -File .\run_research_platform.ps1 -Mode Test
powershell -ExecutionPolicy Bypass -File .\run_research_platform.ps1 -Mode Single -Method GA -Output research_platform/runs/my_ga_001
powershell -ExecutionPolicy Bypass -File .\run_research_platform.ps1 -Mode Verify -Output research_platform/runs/my_ga_001
# 1096 个 CloudSim 案例与 27 条主求解轨迹
powershell -ExecutionPolicy Bypass -File .\run_research_platform.ps1 -Mode Matrix -Output research_platform/runs/my_matrix_001
# 图 2-26：独立的 1296 次求解，需要完整 Matrix
. .\runtime.ps1
$researchTools = Get-ResearchJavaTools
$researchPython = Get-ResearchPython
& $researchTools.Java -Xmx2g -cp 'bin;lib/*' repro.ResearchFigureBenchmarkV10 research_platform/runs/my_matrix_001 research_platform/runs/my_matrix_001/report/figure_benchmark
if ($LASTEXITCODE -ne 0) { throw 'Scale benchmark failed' }
& $researchPython tools/research_figure_report_v10.py --run research_platform/runs/my_matrix_001
if ($LASTEXITCODE -ne 0) { throw 'Figure audit/report failed' }
```

Single 支持 FFD/BFD/GA/GGA/BFD-GA；也支持 -Mapping 指定自定义映射。每次执行仿真使用新目录，失败目录保留诊断。Verify 只核验已有完整数据并更新核验报告；摘要 v09 基线不能 Verify。历史运行包含生产绝对路径，直接搬移后的 Verify 不受支持；重新执行新运行以获得当前地点的完整证据。

默认配置每个键只出现一次，GA/GGA 原生目标为 server_only，BFD-GA 为 total。能耗实验使用 feasible_packing；规模入口明确覆盖为 random_hosts，关闭种子解。两类试验的初始化用途不同，不代表作者唯一实现。legacy_v08.properties 为历史配置，修改两个算子开关并不等同完整回退历史版本。

## 源码职责与构建边界

| 清单/文件 | 职责 |
|---|---|
| build/current.txt | 当前 Research 主链、V10 规模入口与内部算子 |
| build/shared.txt | 共享物理/轨迹/调度类；含 Simulation 的旧放置传递依赖 |
| build/legacy.txt | 历史实验入口；默认不构建 |
| ResearchPlacement.java | 放置公开 API、方法选择、进化循环、自检 |
| PlacementOperators.java | 包内修复、分组、初始化、对齐和变异算子 |
| ResearchPolicy.Controller | 自定义在线控制接口，例子见 ResearchExampleController |
| ResearchDatacenter.java | 实际事件、迁移约束和能耗积分 |
| ResearchConfig.java / SupplyPowerModel.java | 参数校验与供电模型 |

保留 src/repro 路径和包名以兼容调用；PaperSettings、PaperHost、PaperTrace 仍是当前共享依赖，不能按历史名称删除。build.ps1 默认 Current；需要历史入口时执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1 -Profile All
powershell -ExecutionPolicy Bypass -File .\tests\check-placement.ps1
```

重构回归基线捕获于 Git 提交 4a3f487，涵盖 240 组真实输入、随机种子和算子配置，验证最终及逐代方案。构建清除 bin 内生成的 class，防止 All 的旧入口残留；源码清单新增文件须同步登记。新运行的 source_snapshot/provenance.csv 还归档构建清单、运行脚本、Python 核验工具与依赖声明。

## 历史证据与封存

完整数据见 [历史数据索引](../历史数据索引.json)。旧报告、源码快照、封存清单保持生产原字节；当前工作树不再声称与旧清单完全相同。research_ga_final_v10.py 是历史对照工具，包含非 BFD-GA 结果与 v09 相同的断言，创新修改后不能机械套用。

封存工具保留历史文件名，但现在必须显式指定项目之外的新目标，不再自动生成旧名称或改写旧索引。先选取一个不存在的目标目录：

```powershell
. .\runtime.ps1
$researchPython = Get-ResearchPython
& $researchPython tools/package_ga_fix_v10.py --output ..\..\V1_release_001
if ($LASTEXITCODE -ne 0) { throw 'Package failed' }
```

默认封存当前代码与项目已有历史结果；可用 --run 指定完整历史 Matrix 的报告来源。封存生成新的 SHA-256 清单，状态 COPIED_HASH_VERIFIED 仅表示复制完整性，不表示当前代码已重新生成历史报告。不会重复复制主矩阵原始 CSV。新副本应再执行 Test 和新的 Single/Verify。目标存在、与源码或报告目录重叠、来源缺失均拒绝；失败副本保留诊断，重试使用新目标。

同构机架标签对齐不直接适用于异构 UPS。迁移控制、资源假设、精度与停止判据的重建边界见 [物理依据](research_platform/物理假设与论文依据.md) 和 [历史最终说明](../结果/GA与图2-26最终修正说明.md)；实现 PASS 不等于论文完整趋势恢复。
